Indexing

Oct 29, 202623 min read

  • architecture
  • index

Crate: index. The index turns files and rows into a graph by deriving what sources don’t know: symbols, links, outlines, embeddings, stack frames. It is exposed as IndexSource, so its output is just more nodes and edges.

Index storage rechecked 2026-10-27 (ADR-0030); extractor coverage from 2026-10-24 (WP-21/WP-65/WP-22/WP-66)

  • Extractors: wiki-links and tree-sitter definitions for Rust, Julia and Python. The three languages run through the same dispatch. Definitions have location ids, names, ranged occurrences, lexical containment and provenance; syntactic calls/references resolve unique same-file names and explicit folder imports (WP-22, 2026-10-28), preserving other targets as Unresolved. See Code Graph Schema for exact coverage and limitations. No headings/front matter nodes yet.
  • Parsing is native tree-sitter through arborium (shared with the Rust code editor, P-113) — not .wasm grammars; the index runs on desktop and the server, and the web/phone query the server’s.
  • Default code graph reads use Sophia in files-truth folders on desktop/mobile and the server. The in-memory graph, BM25 postings (search.rs) and embeddings (brute-force cosine, reciprocal-rank fusion) rebuild on open; search and explicit/fallback graph reads use them. Marked store-truth folders use the read-only stopgap below. No tantivy, usearch or recoco dependency.
  • Content identities: experimental moonkale-index/content-ids, off by default. Explicit async requests hash normalized Rust/Julia/Python syntax and same-file recursive dependencies; a bounded memory cache and optional state-store adapter are available. Unsupported syntax fails explicitly. No eager workspace hashing or UI activation. See Code Graph Schema for normalizer v7 and its conservative syntax subset.
  • Rust L1 foundation: default-off lossless-syntax snapshots preserve exact bytes/trivia and return guarded pure patch plans. The separate default-off structural-edits host feature now connects these plans to revision-aware document buffers and graph preview/conflict controls on desktop/web, plus complete same-folder reference-aware Rename via the existing LSP manager (coordinated buffer history, separate per-file saves); see Rust Lossless Syntax and Patches.
  • LSP as a second extractor and the precision field are not built.
  • Stack traces live in their own crate, moonkale-trace (TraceSource), not in index::trace.

Folder truth (ADR-0030, implemented 2026-10-27)

Opening a folder detects .moonkale/truth.json: {"truth":"store","since":"2026-10-27"} means store truth; no marker (or explicit truth: files) means file truth. The folder and index descriptors carry this mode. The shared folder detector bounds the JSON to 4 KiB and refuses invalid, unreadable or linked metadata; it never silently authorizes cache disposal when metadata cannot be trusted. See ADR-0030 Where the truth lives for the format and future migration commands.

The status bar and explorer root show “Truth: files” or “Truth: Sophia store” in English, German and Chinese. The status item follows the active document or Explorer selection, falling back to the first folder. Its tooltip lists each open folder’s name, truth, backend and fallback/read-only reason. Until SPEC-010 is implemented, marked folders show “Code graph read-only: store editing is not available yet”. Their graph and search read the in-memory index; the code store is left untouched. Plain file editing remains available, without propagating changes into the authoritative store. There is no marker-creation or truth-move command yet.

FolderStore refuses all writer/check/repair entry points for store truth, before SQLite is opened or any store/sidecar/ignore file is created or removed. This covers automatic broken-cache repair, manual Check the cache and normalizer changes, even when the existing store is unreadable. The writer retains store truth and rechecks the marker on each entry point. The cache behavior below applies only to files-truth folders.

Sophia folder cache (WP-21, implemented 2026-10-24)

With sophia enabled by default on desktop/mobile and by the server feature, opening a files-truth folder writes the index’s code records into .moonkale/code.sophia (SQLite, enforced derived mode). The existing in-memory index and its search remain available. The extra Sophia Source offers names, definitions, references, generic Calls, SQL and Sophia queries to the graph view and agent. It is read-only and declares file truth (ADR-0029).

Only the index’s admitted Rust/Julia/Python code enters it: not hidden or ignored, under 512 KiB per file; 5,000 walked files and 64 MiB aggregate bound. Metadata files are read only for naming, never copied into the store. The walk explicitly excludes .moonkale/; the cache adds its own ignore file. Reopen hashes text against manifests and skips unchanged code without parsing or ingesting it. Julia uses the shared module/include resolver; its dependants are recomputed when needed and only changed manifests are written. Rust uses nearest Cargo package names and conventional file modules; Python uses package roots. Nonstandard Rust #[path] / custom target module trees are not inferred by this first writer. Shared naming and content-id limits remain authoritative.

One watcher debounce window crosses Source::refresh_batch and the server proxy intact, then becomes one replace_files transaction, including both sides of a rename. Structured name conflicts add owners with a 16-owner bound; empty/repeated owners fail visibly. Normalizer mismatch rebuilds the derived cache. Removing it loses no authored content. Sophia manifest @1 owns facts and their per-file reference counts, including atomic rollback.

The adapter checks current file hashes on text fetch. Matching definitions use exact source spans; stale spans fall back to the current whole file and mark the path stale. No reprinted code is written back. A derived reader reopens its cache connection per call so it can follow cache recreation. Rebuilding preserves definition content ids and names; generic nominal ids are allocated by Sophia and may change. ADR-0030 makes this the default for legacy code graph reads; search remains in memory.

code_graph.source in the regular user/workspace settings store selects auto (default) or in-memory. The graph’s bounded code-graph query envelope carries this preference per request; it never changes search or another client’s choice. The index delegates code graph queries to its read-only Sophia adapter. File/note nodes and wiki-links remain index-owned; Local code-file queries use manifest spans to reach stored definitions. The status bar always names the backend, including an explicit reason for fallback. A cache directory/open, sync or read error preserves the current index. A corrupt database is rebuilt once per open; an authored store at the reserved path is never deleted.

Check the cache in the command palette takes a new bounded, ignore-aware snapshot of current files, builds a fresh store in a temporary directory under .moonkale/, and compares the shared folder_store::digest full-digest-v1 implementation used by the history replay. It checks manifests, names, live generic memberships, canonical record bytes, text pointers and facts. A fresh cache reports same; differences name keys, rebuild the cache, and file a problem in the runtime log and status notification. Temporary stores are cleaned on return. Cache export awaits SPEC-010’s text form.

Rust acceptance tests live in packages/services/index/tests/folder_store.rs; producer/mapping details in packages/services/index/index.md, reader details in packages/sources/sophia/sources-sophia.md. Reproduce the repository measurement with cargo run -p moonkale-index --example folder_store --features sophia -- . (native debug; reads current working-tree code).

Decisions

  • tree-sitter grammars as .wasm — one artefact for desktop, web and mobile; contributed by language extensions (Contribution Points).
  • Two symbol extractors: tree-sitter (fast, always available, approximate) and LSP (precise, needs a server). Derived edges carry precision; views prefer LSP when both exist.
  • Incremental by node: a change re-runs extractors for that node only and re-links only its edges. Priority goes to nodes that are visible in some editor.
  • Storage is native/server: tantivy + usearch don’t target the browser; the web build queries the server’s index. Parsing still runs client-side for highlighting.
  • Sophia is the persisted code graph and query engine (ADR-0029). Recoco/Thread remain requirements prior art, not pipeline dependencies.

Stack traces and ASTs

index::trace parses rustc/Julia/Go/Python trace formats into Frame nodes with Calls edges, linked to Symbol nodes. A panic in the Terminal becomes a clickable subgraph in the Graph View with a hierarchical layout. Function ASTs are the tree-sitter tree exposed as a GraphView (nodes = syntax nodes) — free once parsing exists.

Embeddings and RAG

See LLM and RAG. Chunking is per symbol / heading / row; vectors are stored locally (usearch) or in the source when it has VECTOR (pgvector, HelixDB). Hybrid search = BM25 (tantivy) ∪ vector, fused.

Interface::all first builds Contains edges, then asks edges_at(Out) for each retained namespace. That calls children_in, rebuilds child views and Contains edges, and finally all discards those edges through its dependency filter. The Moonkale answer has 1,000 namespaces, no definitions/names, 999 Contains edges, and is truncated; generic-call expansion therefore has no subjects. The namespace child probes construct 4,871 children, despite the answer’s cap. Lenticulum’s same-sized answer has only 74 namespaces; its child probes build 1,085 children. Namespace count and metadata-table size explain the difference in work despite the identical 1,000-node cap. No text rendering or per-definition lookup is needed for this answer.

children_in calls meta_prefix once per namespace. Its SQLite substr predicate scans all metadata; EXPLAIN reports SCAN t_meta. The corresponding 1,000 prefix probes return zero rows yet take most of the all-read time. namespace_exists also uses names_under(path, 2), whose OR predicate reports SCAN t_name. names_from instead reports an indexed primary-key search. The metadata/file-manifest scan explains why deleting historical definitions alone did not remove the delay.

The visible legacy code graph retains Sophia ids. Consumers requiring an index node call Workspace::index_node: unique native key first, otherwise the cache’s file and exact byte span with a matching input digest. Structural edit and rename controls use this path; search and explicit query views keep their existing source routes. A single-member nominal function can resolve to its body. Overloads, shared bodies, stale inputs, unrelated stores and bounded-read overflow leave the controls without an automatic edit target. The existing revision-aware proposal and LSP guards still apply. See P-233 Structural edits need index nodes in the graph.

Cross-file calls and references (WP-22, 2026-10-28)

The folder graph resolves a use only through an explicit admitted import and a unique indexed target. Rust supports simple use a::b::f and use crate::m::f through conventional mod declarations and m.rs / m/mod.rs, rooted at lib.rs or main.rs; inline modules contribute namespaces. Python supports from m import f and import m followed by m.f, with folder-relative module paths. Julia supports using M: f, import M.f and qualified M.f for modules defined in the indexed files. Module imports stay in their enclosing module; function/conditional imports, aliases, import lists, wildcards, re-exports, custom Rust targets/paths and implicit Julia include ownership are outside this resolver. Attributed Rust module paths/imports, unsupported import environments, duplicate module owners/targets and possible local shadows remain unresolved; no package loader, compiler or execution runs.

Resolved Calls and References carry resolved_via: import, import (one contributing statement), imports (a JSON list of contributing statements) and import_target, alongside input provenance, count and occurrence ranges. Julia’s directly qualified form records the qualified spelling as its import provenance. Same-file edges do not gain these properties. Content normalizer v7 and lazy identity semantics are unchanged: import edges are annotations, not new content-hash inputs.

Each extraction retains its unresolved base facts. After a watcher batch, a folder-wide in-memory reconciliation builds a namespace/name lookup and updates changed origin projections. It uses admitted facts and does not fetch or reparse unchanged callers. Removing, moving, duplicating or restoring a target therefore updates incoming dependencies, including uses that were unresolved before. The existing file/text walk bounds apply; the cache snapshot also retains its 64 MiB aggregate bound. No recursive dependency fetch is added.

Sophia stores import_edge annotations owned by the caller’s file manifest. The annotation identifies the target by file, exact span and source digest; its reader requires that matching current manifest before adding a graph edge. Annotations cap at 64 KiB; overflow refuses cache sync with a visible fallback reason instead of silently dropping a dependency. Import resolution retracts cross-file edges if incremental additions exceed the 5,000-file walk budget. Content-deduplicated callers share one edge with combined counts/ranges and an origins JSON list. A selected debounce batch never combines another dirty caller’s new source with old normalized records; that caller waits for its own event, while target-source guards suppress outdated edges. Only admitted normalized definitions enter this projection; unsupported bodies and file-level uses retain the in-memory graph as the fuller fallback. A target edit atomically replaces its manifest and affected caller annotations. Reused syntax facts avoid reparsing unchanged inputs within a writer lifetime; after a no-op reopen the first edit warms that bounded syntax cache. Unchanged callers’ records are reused rather than normalized again. Manifest-hash reopen still performs zero parses/writes. The derived producer stamp is now moonkale-wp66-imports-v1@7, causing an ordinary cache rebuild once, while preserving existing content digests and all store-truth protections.
