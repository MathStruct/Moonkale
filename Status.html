Plot quick look (WP-40, 2026-10-30)

✅ Done 2026-10-31. Optional default-on Plot adds a linked SVG panel from any held table result, with automatic line/scatter/bar/histogram, column/mark controls, linear/log/time axes, equal aspect, zoom/pan, hover and keyboard row selection. SQL page bounds are retained and incomplete results are marked partial. Database aggregation, publication export, live data and saved chart specifications remain later. See Plotting Requirements.

Proposals and optimistic text writes (WP-49 first slice, 2026-10-30)

◐ Text slice built and validated. Local agents queue versioned text changes in one session inbox; two-file and partial review reuse coordinated buffer proposals. Stale text is refused and reviewed with the shared three-way editor. Folder persistence reports ordered saves; normal store-truth Sophia folders preview and apply selected text together in the database. Generated files are not overwritten. Read-only fallback remains for unavailable stores. Accounts, durable task/inbox synchronization and source-provided current author/time metadata remain later work. Eight proposal-model and four Sophia adapter tests, all AGENTS gates, the full CI/default-graph browser matrix and the final rendered review check pass. See Shared Work.

Table pushdown (WP-13, validated 2026-10-30)

✅ Built and validated. SQLite, DuckDB and Turso accept typed sort/AND filters and prepared keyset pages with stable row-key ordering, NULLs last and no OFFSET. Keyboard/mouse header controls hide filters behind column menus; scrolling and Next share bounded pages. Other results show a partial indicator. Edited rows outside the filter remain visible until refresh. Paging retains at most 4,000 rows with a 16-MiB snapshot eviction target and a separate edited-row byte budget. Schema changes refuse merging until Refresh.

All AGENTS gates, three engine reference suites, 13 grid/edit tests, 28 standalone parser regressions and the reconciled full browser feature matrix pass. The million-row fixture completed 1,000 pages at page-to-paint p50 198.95 ms / p95 215.68 ms, with 41 DOM rows maximum and constant 70.125-MiB Wasm memory across the sampled traversal. See Table Editor for bounds and scope.

Crash safety (WP-57, checked 2026-10-28)

Native built-in extension callbacks, tasks, effects and resources now have per-extension panic guards; a failure removes that extension’s contributions and shows one notice. The web’s aborting wasm client has an independent reload / local-copy / safe-mode overlay. Repeated incomplete startups offer safe mode; desktop --safe and web ?safe ignore extensions and saved layout without changing preferences. Both wasm runtimes already created fresh instances and now bound retries to three after the initial failed invocation. Unsaved-buffer snapshots and compiled service hot reload remain unbuilt. External compiled-in extensions must adopt the new callback/task helpers. P-234 fixes a Chromium structural-preview crash by heap-pinning futures before constructing async guard wrappers. See Crash Safety.

Sophia folder cache (WP-21 / ADR-0030, checked 2026-10-27)

Default-on sophia on desktop/mobile, implied by the server feature, writes admitted Rust/Julia/Python code into the derived .moonkale/code.sophia cache and opens it as an additional read-only Source. Reopen skips unchanged files; one watcher window is one transactional batch, including moves and bounded name-owner retries. Stale reads fall back to current files. Legacy code graph reads now default to the cache; search remains in memory. The 2026-10-27 verification passes 867 workspace tests (seven ignored), 81 focused index/Sophia tests including 16 folder-cache regressions. Eight browser suites cover default cache reads, persisted override, visible fallback, repair, watch updates and ordinary graph/search/settings/palette behavior. See Indexing for the passing mandatory gates and desktop/server/mobile/Android compilation checks. The final defaults-only Sophia and Local browser checks also pass. The setting code_graph.source = auto | in-memory and the status-bar backend item expose the choice and fallback reason. A corrupt cache gets one rebuild attempt; Check the cache compares a fresh temporary store with the replay digest, repairs differences and logs/notifies the problem. Browser-only builds keep the in-memory path or use their server.

Native debug measurement on Moonkale: 8.830 s cold / 0.664 s reopen, including new folder snapshots; store work alone 8.101 s / 0.030 s. 36,704,256 bytes for 478 files / 6,111,526 source bytes. Reopen performs zero parses or replacements (timings rounded independently). The normal form refuses 2,787 definitions and reports 12 ambiguous named bindings; this is partial syntactic coverage. See Indexing for methodology, module-naming limits and evidence. ADR-0029’s four default gates are met; ADR-0030 authorizes this legacy-folder default.

Folder truth (ADR-0030, checked 2026-10-27)

Folders detect the bounded .moonkale/truth.json marker on open and carry truth: files | store in folder/index descriptors. The status bar and explorer root label the truth in English, German and Chinese. The status bar shows only the active document’s or selected Explorer folder’s truth and code-graph backend (first folder when neither applies); its tooltip lists every folder and any fallback or read-only reason. Marked folders use the in-memory code graph with an explicit read-only explanation until SPEC-010 lands. Plain file editing/search remain available; code-store writes, cache checks and repairs are refused, preserving even unreadable stores and SQLite sidecars. No command creates a marker or moves the truth yet. Generated files, outside-edit proposals and New project remain planned. See Indexing and ADR-0030 Where the truth lives. All AGENTS gates pass (871 workspace tests, seven ignored); the focused folder/index/Sophia run passes 118 tests and the sophia-folder browser suite checks both labels and the read-only explanation.

Sophia history replay (checked 2026-10-24)

ADR-0029 gate 4 now uses reproducible Git-history replay in place of unavailable daily use of the optional folder store. The opt-in tool and hermetic five-commit CI test are implemented. Real Moonkale and Lenticulum histories expose missing and stale live generic names/memberships despite matching file manifests (P-231 Sophia folder replay loses generic memberships). Sophia fixed P-231 in v0.1.1, which Moonkale pins; with it both replays are clean (0 differences), so gate 4 is met. Search stays on the in-memory index (Sophia has no search dialect). Gate 3 is met through the server; ADR-0030 switches the legacy graph default. Exact runs and measurements are in Indexing; this checks the replay only, not the older whole-product inventory above.

Sophia capped read profile (checked 2026-10-24)

The optional folder store’s slow All(1000) read is traced to Sophia v0.1.1: namespace dependency discovery repeats child enumeration and full metadata scans. Moonkale’s node conversion and generic-call expansion are negligible by comparison. Sophia fixed it in v0.1.2 (Moonkale pins v0.1.4): All(1000) now takes 43 ms debug / 16 ms release, and folder stores collect their own garbage (Sophia SR-146) (P-232 Sophia capped graph reads scan namespace metadata). See Indexing for measurements. ADR-0029’s four default gates are met (2026-10-26; gate 3 by the server fallback, checked in CI). The in-memory index stays the default until Daniel decides.

Graph selection compatibility (P-233, checked 2026-10-28)

Experimental structural edits and rename resolve Sophia cache selections to unique index edit targets while retaining the default Sophia graph. Resolution uses a native key or exact file/span/input provenance; overloaded or shared bodies are not chosen automatically. Both editor browser suites exercise real Sophia ids. See P-233 Structural edits need index nodes in the graph for the consumer audit and validation results.
