Notes for `moonkale-editor-table` (Milestone 2). Design: [[Table Editor]].

`TableExtension` contributes one closable panel per `Table` node in `Workspace::docs.views` (non-text nodes opened via `open_node`, which routes `Table` there instead of into a `Document`). `TablePanel` holds a SQL textarea prefilled with `SELECT * FROM "table" LIMIT 1000`, runs `Query::Text { dialect: "sql" }` on the node's source (Ctrl+Enter or the button), and renders the `Table` in a **virtualised grid** (2026-10-14). Only the rows and columns under the viewport, plus a little overscan, are in the DOM, so the SQL sources' cap could rise from 500 to 50 000 rows. The grid has a sticky header and row numbers, NULL/number/bytes cell styles, and a truncation note. Clicking a header sorts (ascending, descending, off; NULLs last), dragging its edge resizes, and a filter box narrows the rows. A keyboard cursor moves with the arrows, Page Up/Down, Home/End and Ctrl+Home/End, scrolling the cell into view. Sort and filter apply to the loaded rows. The arithmetic (windows, widths, order, moves, reveal) is `grid.rs`, unit-tested without a DOM; `table-grid.mjs` scrolls a 50 000-row result in the browser. The source enforces read-only; the error text is shown verbatim. A source that answers two dialects (`Capabilities::text_dialects`, a Sophia store's `sql` and `query`) gets one button per dialect before the box. Switching runs the query in the new dialect, and an untouched default text follows it (`select p, d where name(p, d)` for `query`). Not yet: pushdown sort/filter/pagination, editing.

**Milestone 3:** the query language follows the source's `capabilities.text_query` (`sql` or `cypher`; the default query is `MATCH (n:Table) RETURN n LIMIT 200` for Cypher). When a result carries nodes/edges (Ladybug path queries), a **Show in Graph** button sets `Workspace::graph_request`, and the Graph panel switches its source picker to that database and draws the query's result.
