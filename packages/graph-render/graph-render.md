Notes for `moonkale-graph-render` (Milestone 2). Design: [[Graph View]], [[ADR-0011 Desktop graph surface strategy]] (plan A).

**A standalone wasm module**, not part of the app's wasm: built by `build.sh` (`cargo build --profile graph-wasm --target wasm32-unknown-unknown` + `wasm-bindgen --target web`) into `../graph/assets/graph_render.js` + `graph_render_bg.wasm` (2.4 MB), loaded by the host panel via dynamic `import()` — the same way in the browser and inside the desktop webview.

- `graph.rs` — input JSON (`nodes[{id,label,kind,key}]`, `edges[{a,b,kind}]` by index), colours by kind, deterministic spiral start positions, degree-based radius.
- `layout.rs` — Fruchterman–Reingold with cooling, gravity, pinned nodes; O(n²); stops at temperature < 0.3 or 600 iterations. Native unit tests.
- `camera.rs` — world↔screen, pan, zoom-at-pointer, fit, nearest-node hit test. Native unit tests.
- `render.rs` — wgpu 30: `new_instance_with_webgpu_detection` (WebGPU when real, else WebGL2), surface on the canvas, two instanced pipelines (edges as thin quads, nodes as SDF circles), alpha blending, camera uniform. `shaders.wgsl`.
- `web.rs` — `create(canvas, overlay, onEvent)` → `GraphView { set_graph, fit, relayout, resize, backend, node_count, node_screen_position, destroy }`; rAF loop (more layout iterations per frame for small graphs); pointer handlers (pan, drag node, hover, click/dblclick, wheel zoom); labels on a 2D-canvas overlay with LOD.
- Camera policy: auto-fit after `set_graph`/`relayout` once the layout settles, **never** after the user has panned, zoomed or dragged (P-051). Dragged nodes stay pinned until Relayout.
- Events: `ready{backend}`, `hover{id,label,nodeKind,key,x,y}`, `click{id}`, `dblclick{id}`, `settled`.

Known: `create()` hangs if the canvas can't get a GL context — the host probes first (P-049). No GPU text, no picking buffer (CPU hit test), O(n²) layout: all listed in [[Problem Ranking]] R-22.

**P-068 (Milestone 4):** node attributes use explicit offsets (0, 8, 16) because `NodeInst` pads `radius`; `vertex_attr_array!` had put the colour at 12, dropping the red channel of every node since Milestone 2.

**Colours (Milestone 3):** `InNode.color` / `InEdge.color` (`#rrggbb`, optional) override the kind-based palette so the host can colour per database label; `parse_hex` in `graph.rs`.

## Milestone 6: scale
- `quadtree.rs` — Barnes–Hut: a quadtree rebuilt every step, `force(i, x, y, k2, theta)` approximates cells with `size / d < θ` by their centre of mass; θ = 0.8 (unit tests compare θ = 0 with the exact sum). `layout.rs` uses it from `BARNES_HUT_FROM = 1500` nodes; below that the exact O(n²) loop stays (cheaper for small graphs). Iteration caps: 600, 250 above 10 000 nodes, 120 above 50 000.
- `web.rs`: labels off above 20 000 nodes; fewer layout iterations per frame for big graphs; `bench_layout(n, steps)` export (synthetic graph, ms/step) used by `packages/web/tests/e2e/bench.mjs`; `examples/bench_layout.rs` is the native twin.
- Numbers (ms/step, Ryzen 7 7800X3D): native 1k 1.2 · 10k 12.9 · 50k 79.4 · 100k 169.3; wasm/Firefox 1.8 · 15.3 · 85.7 · 189.3. Recorded in [[Milestone 6 - Implementation Log]]. WebGPU compute stays deferred (not needed).

## Milestone 8: 3D
- `graph.rs`: `Node.z` from `layer_z(kind, i)` — one plane per kind (directory −2, file −1, page 0, symbol 1, block 1.5, database −1.5, table −0.5, columns/rows/vertices/keys 0.5, commit 2; ×140 units) plus a deterministic jitter.
- `camera.rs`: `three_d`, `yaw`/`pitch`/`dist`, `cz`; `view_proj()` (column-major perspective × look-at, y-down world), `project(x, y, z) → (sx, sy, w)`, `size_factor(w)`, `orbit`, 3D `pan` (target moves in the camera plane), `zoom_at` (dolly), `fit` (bounding sphere in the 50° field), `hit` in projected space; `uniform()` is 28 floats (2D fields, mode, viewport, dist, `mat4`).
- `shaders.wgsl`: `project()` branches on `camera.mode`; nodes are screen-space billboards with radius attenuated by `dist / w`; edges get a screen-space normal from projected endpoints; both carry depth and a fog factor toward the background.
- `render.rs`: instance positions are `vec3`; a `Depth24Plus` buffer with `LessEqual` (2D writes depth 0.5 everywhere, so order still wins there).
- `web.rs`: `set_mode("2d"|"3d")`, `mode()`, `Drag::Orbit` (right button or Shift), context menu suppressed on the canvas, labels and `node_screen_position` through `project`, far labels only when hovered. Rebuild with `build.sh`.
- Tested: `camera` unit tests (projection centre, attenuation, behind-camera) and `graph3d.mjs` in Chromium + SwiftShader (P-082) — the first suite that runs the renderer.

## Milestone 9
`Camera::basis()` (forward/right/up in the y-down world) and `unproject(sx, sy, w)`; in 3D a node under the pointer drags in its own depth plane (`web.rs` `Drag::Node`), pinned like in 2D. Test `unproject_inverts_project_at_the_same_depth`.

Android (P-089–P-091): `create(canvas, overlay, onEvent, prefer)` takes an optional backend hint — `"gl"` makes `Renderer::new(.., gl_only = true)` skip WebGPU, which the Android WebView advertises but never finishes creating a device for. `Renderer::new` prefers the first **non-sRGB** surface format from `get_capabilities` (the shaders write linear colours; sRGB on WebGL2 gave a grey canvas). `resize()` re-runs `Camera::fit` while `auto_fit` is still set, so a canvas that gets its real size after the layout settled (a hidden phone tile) — or a panel the user resizes before touching the graph — stays fitted. The 2D fit scale clamps at 12 so a five-node vault fills a phone screen.

Touch (spec 006): `State.touches` tracks touch pointers (captured on down, dropped on up/cancel); two fingers → `Drag::Pinch { last_dist, last_angle, last_mid }` — `zoom_at(dist / last_dist, mid)`, `pan(Δmid)`, and in 3D `yaw -= Δangle`; one finger left continues as a pan without a click. `pointerleave` ignores captured touches. `GraphView::camera_state()` for tests.

Incremental `set_graph` (spec 017): with ≥ 50 % shared node ids, positions/pins carry over, new nodes start at their known neighbours' mean, the layout is warmed (temperature 3) only if the node set or edge count changed, and the camera is not touched; otherwise a fresh layout + fit as before.

**Drags survive a replaced graph (P-155, issue #12):** `Drag::Node` holds the node's `id` with the last index as a fast path — `set_graph`/`unstash` can replace the graph while the pointer is held, which made a bare index stale (out of bounds → panic, or another node). Every move re-resolves by id, follows the node to a new index, and ends the drag when it is gone. `graph3d.mjs` replaces the graph mid-drag as a regression test.

Graph quality (2026-09-20): `layout.rs` — attraction divided by `1 + 0.5·ln(1+max degree)` (hubs pull less), gravity 0.12 for degree-0 nodes; `graph.rs` — `fit_bounds()` over the connected majority; `web.rs` — labels placed by importance with a rectangle collision test (≤ 400), `layout_state()` export.

Zoom floor and fit-while-settling (2026-09-21, P-100): `camera::MIN_SCALE = 0.002` (was 0.05) for `zoom_at` and `fit` — the Moonkale repository's 2 851-node layout spans more than the old floor could show, so the whole graph could neither be fitted nor zoomed out to; nodes keep a 2 px minimum radius in the shader so a zoomed-out graph is a cloud of dots. `web.rs` re-fits an untouched view (`auto_fit`) on every frame while the layout runs, not only when it settles, so a big graph is on screen from the first frame.

**Spec 031, stage 0 (2026-10-08): persistent instance buffers.** `render.rs` no longer re-creates the vertex buffers every dirty frame (`create_buffer_init` at 100 k nodes + 120 k edges was ~9 MB allocated per frame). Each pipeline takes two instance slots instead: slot 0 the geometry (`NodePos { pos }`, `EdgePos { a, b }`), slot 1 the appearance (`NodeAttr { color, radius }`, `EdgeAttr { color }`); the buffers are persistent, grow to the next power of two of the instance count, and a half is uploaded only when its revision moved — `pos_rev` (every layout step, a node drag) or `attr_rev` (a graph swap, a hover, a mode switch). `State` owns both revisions and bumps them where the data changes; `Renderer::draw` caches what it already uploaded. `draw_stats()` exports the accumulated `Renderer::draw` time and frame count, measured by `bench-draw.mjs` (Chromium + SwiftShader, the graph3d setup). Numbers, 100 k nodes / 120 k edges: settling 1.91 → **1.14 ms** per drawn frame; hover on the settled graph 1.88 → **0.89 ms**. Bench lesson: dx serve content-hashes the assets — after `build.sh`, restart it (or compare the served bytes) or the browser measures the previous module.

**Spec 031, stage 1 (2026-10-08): edges and selection.** `frame.rs` — the pure scene → instance bridge: `build_frame(graph, three_d)` tessellates each edge into segments (parallels bow apart in half-steps of `BOW_SPACING` world units, the exact middle staying straight; a self-loop becomes a 16-segment ring resting on its node), places arrowheads at directed ends (`directed` implies a target head; `arrow: source|target|both` overrides; heads point into their node and are 2D-only), and `edge_at` picks the nearest segment within its stroke's reach. Native unit tests cover the fan-out, the ring geometry, head placement and picking. The wire format grew `#[serde(default)]` fields on `InEdge` (id, directed, width, dash, opacity, arrow, label, route) — self-loops (`a == b`) are no longer dropped; ids default to `{a}:{b}:{i}`. `render.rs` draws three pipelines now (segments with per-instance width and a screen-pixel dash, rotated triangle arrowheads, nodes), caching the built frame until a revision moves — a camera pan re-draws without rebuilding. Selection (spec 031 §5) is by **instance id** in `frame::Selection` (it survives an incremental `set_graph`): a plain click picks a node, then an edge, then clears; Ctrl/Meta toggles; a released drag or pan selects nothing; every change emits `select {nodes, edges}` and `selection_state()` reports it for tests. Selected nodes wear a light shader ring; selected edges lift their colour and thicken. `shaders.wgsl` is validated natively (`shader_tests::shaders_validate`, naga — a WGSL typo used to park every panel behind a runtime wgpu panic). E2E: `graph-edges.mjs` (parallels picked apart, Ctrl adds, drag selects nothing, the loop picked on its ring). 3D keeps plain edges: no heads, curves project as-is.

**Spec 031, stage 2 (2026-10-09): ports and edit mode.** The wire format grows `InPort { node, name, color, side, offset, direction }` under `InGraph.ports`, and `InEdge` gains `a_port`/`b_port` — an edge anchored at ports starts and ends there (a stale name falls back to the node's centre, never breaking the geometry). `frame.rs`: `port_world` (side-based placement, `PORT_STANDOFF` beyond the rim, `offset` 0..1 spreading ports along the side) and `port_at` (independent hit targets, spec §2). Ports draw as small circles on the **node pipeline** — no new pipeline: `node_count = nodes + ports drawn`, edit mode only; the wire being dragged draws as one extra segment instance. `set_interaction("explore"|"edit")` switches the mode (spec §5; `set_mode` stays 2D/3D) without touching the camera; in edit mode a pointerdown on a port starts `Drag::Wire`, the pending wire follows the pointer (at the source port's depth in 3D), and a release on another port emits `connect {from: {node, port}, to: {node, port}}` — the host validates types and adds the edge; the renderer never mutates topology (§7). A second finger, a leave or a cancel drops the wire. `DrawInput` groups the draw call's parameters (stage 2 grew them past nine arguments). Tests: ports' placement, anchored edges, stale-name fallback and `port_at` natively (25 tests); `graph-edit.mjs` e2e — ports appear only in edit mode, the camera survives the switch, a wire to `b:in` emits `connect`, a wire to empty space cancels, and the frame still holds one edge (the renderer did not add it).

**Spec 031, stage 3 (2026-10-09): layers and traces.** `InLayer { id, name, color, visible, overlay, width, dash, opacity }` and `InTrace { id, layer, steps: [node ids], color }` join the wire format; nodes and edges carry `layers` membership (empty = the base scene, always drawn). `build_frame` emits **one stroke per visible layer** — a shared edge shows both, as offset parallels (`LAYER_STROKE_SPACING` per rank, bowed like the parallel fan-out); the first visible layer styles its stroke (colour, width, dash, opacity). Edges whose layers are all hidden vanish; nodes in only-hidden layers keep their instance slot (hover and selection stay index-aligned) but draw at alpha 0 and answer no hit. Traces are **ordered occurrence walks** (§3): steps resolve to node positions by id (stale ids skip), each hop draws a segment with a head at its end so the sequence reads as a directed walk — recursion revisits ids and the emission keeps the order; a degenerate hop (a frame into itself) draws nothing. Trace hops are owned `None` in `seg_edge`: drawn, but never picked as an edge — layers add presentation, never topology. `set_layer_visibility(id, on)` flips a layer and bumps both revisions; `layer_state()` reports for tests. Segment attributes now come from the frame (layer styling baked there) with selection brightening on top. Tests: styling, hiding, the shared edge's two strokes, the ordered walk and its pick-immunity natively (29 tests); `graph-layers.mjs` e2e — the blue calls + yellow trace layers, 21 segments with both on, 4 hop heads, hiding each layer removes exactly its strokes, restoring brings the count back.

**The stage 0–3 review (P-159, 2026-10-09).** Ten defects fixed, each with a geometry or pixel test: arrowheads point along their edges (the shape reads in the unrotated quad; NDC's y-up mirrors the world angle — sine negated — and `graph-edges.mjs` checks the head's lit centroid); two-way links bow apart (the sign flips when `a > b`); a wire drag survives graph swaps (held by node id + port name, re-resolved every move); the pending wire's style uploads with its positions (`end_wire` bumps both revisions); a shared curved edge counts its route's bow once; 2D↔3D re-uploads arrow positions; dashes continue across sub-segments (`SegAttr.phase`, the arc length, converted by the camera scale in the vertex shader); a 4 px press dead zone keeps touch taps clickable; negative-bow loops touch their node; port-anchored heads pull back by the port, not the node. Perf: hover got its own `hover_rev` and selection its `sel_rev` — hover no longer rebuilds the frame or segment styles (0.82 ms/frame at 100k, was 1.6 mid-review) — and `build_frame_into` reuses the frame's and the polyline's buffers across a layout's frames (settle 4.37 ms/frame; stage 0's 1.14 drew no curves, dashes, heads or layers). `pnglit.mjs` decodes screenshots for the suites' pixel checks; `run-all.sh` runs the three new graph suites.

**Spec 031, stage 4a (2026-10-09): delta updates.** The wire format grows `InDelta { add_nodes, remove_nodes, add_edges, remove_edges }` — every entry names its instance by **id** (edge endpoints are node ids, not indices), and `InDeltaNode` carries `pos` (the start position, for a collapse placing its aggregate where the group sat) and `pinned`. `Graph::apply_delta`: removals first (survivors remapped by `Vec<Option<usize>>`; a removed node's edges and ports go with it), then additions (an id that exists replaces in place; a new node starts at `pos` or spirals out from the centre; an edge whose endpoint is missing is skipped and re-resolves on a later delta — "waiting" is a property of resolution, not stored pending state), then `recompute_degrees()` (degree + radius) and `with_bows()` — both idempotent, so any delta sequence lands in the same state. `with_bows` became `pub(crate) fn (&mut self)` and stores `edge.bow` instead of recomputing routes. `GraphView::apply_delta(json)` warms the layout (temperature 3, new nodes settle next to where they were put) without touching the camera or auto-fit; hover and any pending wire end (indices shifted); selection is id-keyed so it survives untouched. `node_count()` is joined by `edge_count()`. Tests: 4 native (survivor positions kept, a missing endpoint waits and later resolves, re-add replaces, bows equal for a two-way pair regardless of arrival order); `graph-delta.mjs` e2e — a collapse delta (b out, an aggregate in, two proxy edges in) keeps node/edge counts, the camera and the selection; the reverse expand restores the scene. All seven graph suites pass. This is the host's wire for stage 4b's collapse/expand — the renderer never mutates topology, the host sends the delta (spec §7).

**Spec 031, stage 4b (2026-10-09): groups, hulls, focus and LOD.** `InGroup { id, label, members (node ids), color, visible }` joins the wire format under `InGraph.groups`, and `InDelta` grows `add_groups`/`remove_groups` (both by id, replace-on-re-add like nodes and edges) — a collapse re-sends its group with the aggregate among the members; `Graph::apply_delta` remaps member indices through the survivor remap. `frame.rs` emits one `HullPos { center, half }` + `HullAttr { color, corner }` per **visible** group with visible members: the axis-aligned box of the members' rims padded by rim + `HULL_PAD` (7), tinted by the group colour at `HULL_FILL` (0.16), corner `HULL_CORNER` (12 world) — 2D only (3D keeps plain nodes and edges, like arrowheads). Nested and overlapping groups each emit their own instance; alpha blending stacks the tints. `render.rs` draws a 4th pipeline (`hull_vs`/`hull_fs`, rounded-rect SDF in screen px, fill + a 0.45 rim band) **first**, so the tint sits behind; in 2D every depth is 0.5, so draw order is the layering. `focus(ids)` (web.rs) fits the camera to the named nodes' bounds (padding `max radius + 40`) and ends `auto_fit` — an explicit focus is navigation; `fit()` keeps auto-fit. **LOD is shader-side** (spec §6), so a zoom changes no revision and never rebuilds: `node_vs` marks ports (`kind` slot on `NodeAttr`, 0 node / 1 port) whose projected radius < 2.5 px as `kind 2` and `node_fs` discards them; `edge_fs` dashes only while the segment's **screen** length (`seglen` varying) > 6 px — shorter segments draw solid, or the gaps would eat the stroke; `hull_fs` fades out between 6 and 14 px of the smaller half-extent. `frame_state()` grows a 4th element (hull count). Traps logged as P-160: apply_delta's camera contract holds for navigated views (auto-fit re-fits a warmed layout otherwise, P-100), and the dash LOD compares a sub-segment's screen length, so an e2e threshold must measure the edge, not the camera scale. Tests: 4 native (hull box geometry, hidden/gone members don't stretch, nesting/overlap, delta group ops); `graph-groups.mjs` — hue-count pixel checks (a tint is dimmer than any lit threshold — `pnglit.mjs` grew `decode()`), collapse/expand through `apply_delta` keeping counts/camera/selection and re-shaping the hulls, `focus` centring the pair, and the three LOD gates (hulls gone below 0.05 scale, ports gone below scale 0.8, dashes → solid). Bench 100k: settle 4.66 ms/frame, hover 0.92 (stage 3: 4.37/0.82 — the node-attr slot grew to 28 B; no groups in the bench graph, so the hull loop costs nothing there). All eight graph suites pass.

**Spec 031, stage 5 (2026-10-09): higher-order connections.** Three classes over the same nodes, never conflated (spec §2, §8.4). `InHyperedge { id, nodes, color, width, dash, opacity, visible }`: a **junction** — a marker at the members' centroid (radius `JUNCTION_RADIUS` 3 world) riding the node pipeline as kind 3 (no port-LOD suppression — a junction is structural), one spoke segment per member owned by `None` (never picked as an edge: a hyperedge is presentation, never topology). `InSimplex { id, nodes, color, opacity, visible }`: a filled triangle over three members (a repeated id counts once — `distinct_members`; under three there is no face), fanned from the centroid for more; drawn by a 5th pipeline (`simplex_vs`/`simplex_fs`, **TriangleList**, three corners per instance, fill alpha from the colour) between the hulls and the segments; 2D only. `InGroup.highlight`: a clique is a visual membership over the same hull mechanism, wearing twice the tint (`HULL_HIGHLIGHT_FILL` 0.32) and a 0.9 rim (a group: 0.16/0.45). Deltas: `add_hyperedges`/`add_simplexes`/`remove_*` by id, same replace-on-re-add contract as groups; members follow the survivor remap, and a hyperedge under two members or a simplex under three is dropped out of the state (canonical shape). LOD: the simplex fades like the hulls (smallest screen edge 6→14 px); junctions always draw. Bench caution logged as P-161. Tests: 4 native (junction geometry + never-picked spokes + 3D keeps them, simplex triangle/fan, highlight attr, delta round-trip with the collapse interplay); `graph-higher.mjs` — four hue-exclusive pixel checks (a plain group, a highlighted clique, a hyperedge, a 2-simplex over the same five nodes), a remove/re-add delta round-trip proving the classes are independent, and the face's LOD fade with the junction staying. Bench 100k (idle): settle 4.20 ms/frame, hover 0.92 — stage 5 costs nothing when the graph has no higher-order members. All nine graph suites pass.

**Spec 031, stage 6 (2026-10-09): animated edges.** `InEdge.pulse_speed` (world units per second, also on `InDeltaEdge`; 0 = none) moves a Gaussian glow along the stroke — entirely in the segment shader, no new instances, no per-frame CPU uploads: `SegAttr` grows `pulse` + `edge_len` (the whole stroke's world length, accumulated from the tessellation), the vertex positions the glow (`fract(time · speed / len) · len`, constant across a segment) and the fragment brightens toward it by interpolated world distance — so the glow crosses a curve's sub-segments as one continuous line. LOD (§6): segments under 8 screen px stop glowing. The clock: `Camera.time` (elapsed seconds, `performance.now` since the view's create) in the uniform's former `_pad` slot; `State.animates` (recomputed at load/apply_delta/unstash) makes the view redraw every frame while any edge pulses — a pulsed frame moves nothing on the CPU. Trap logged as P-162: the fragment may not read the camera uniform (the bind group is vertex-visibility), so the glow's position is computed in the vertex and passed as a varying — naga's module validation cannot catch a pipeline-interface rule, only wgpu at pipeline creation does. Test: `a_pulsed_edge_carries_speed_and_its_full_length` natively (every sub-segment carries the speed and the stroke's length; the glow needs the phase to find it); `graph-pulse.mjs` — two solid edges at 12 and 36 world/s, the brightness peak along each edge's screen line displaces between captures (the faster one farther; several pairs because `fract` wraps), and at a zoom where the segments fall under the threshold two frames 400 ms apart are pixel-identical. All ten graph suites pass; bench unchanged (no pulses in the bench graph → `animates` false → no continuous redraw).

**The stage 4–6 review (P-163, 2026-10-09).** Claude's review of stages 4a–6 confirmed two bugs and eight candidates; all ten were real and are fixed with tests: `apply_delta` *returns whether it changed anything* (a count-preserving collapse kept the counts and skipped the redraw — the delta e2e now pixel-checks the picture, not the ids); the drag is re-homed across a delta (`dragged_id`/`keep_drag`, #12/P-155 again); a lone edge loses its dead partner's bow (`with_bows` resets singleton groups); the pulse's per-fragment distance is 2D (`.xy` — nodes carry kind-plane z even in the 2D view); the dash and pulse LOD gates read the **whole stroke's** screen length (a 40 px bowed dashed edge drew solid while its straight twin stayed dashed) and `edge_len` is computed only for pulsed/dashed strokes (the pass ran for every edge on every layout step); hyperedge spokes and simplex faces skip layer-hidden members like the hulls do; a delta replace without `pos` keeps the old position, depth and pin (a relabel no longer teleports to the spiral); id lookups go through one owned `HashMap` per call (node ids, edge ids, members — a 2 000-edge delta at 100 k nodes was ~4·10⁸ string compares); `focus` uses the shared `Camera::fit_rect` (3D works, the pad is pixels). E2e measurement traps folded in: the overlay is smaller than the viewport (screen→world uses its own size), the canvas centre holds a node (a pan from there drags it), and a hovered node draws white (park the pointer before pixel probes). All thirteen suites pass; bench 100k: settle 4.45 ms/frame, hover 0.97.

**Spec 031, stage 7a (2026-10-09): the flow shapes on the engine.** The flow editor's migration (ADR-0018) begins with the canvas primitives, host-agnostic and natively testable. `InNode.shape` (`"rect"` — a block; `width`/`height` half-extents, `RECT_WIDTH` 46 / `RECT_HEIGHT` 22 defaults) joins the wire format and `InDeltaNode` (absent keeps the old silhouette, like the position); `NodeAttr` grows `shape` + `height` (36 B) and `node_fs` draws a rounded-rect SDF beside the circle — **a circle ignores the height field**, an early draft ballooned every dot to the 22-world default and three pixel suites caught it at once. Ports ride the rectangle: `port_world` pushes out by the side's own half-extent and spreads along the other axis. `Route::Ortho { stub }` steps a wire out of its source's port, across, into its target (three square-cornered segments, the stub half the gap; parallels shift the step's column), and the arrowheads ride the tangents unchanged. `Graph::hierarchize` is the flow Layout button's core: longest-path ranks → columns (`HIER_COL` 160 apart, centred), rows stacked (`HIER_ROW` 70, keeping the prior vertical order), every node **pinned** — a flow's positions are the host's document, not the physics'; `GraphView::hier_layout` stops the force layout, fits the arrangement, and `node_positions()` harvests `{"id":[x,y],…}` back for the document. Cycles cap at a pass per node (`validate` reports them; the arrangement still spreads the members). Tests: 3 native (ranks/columns/rows/pins + idempotence, the ortho step's corners and head, the rect's side ports) and `graph-flow.mjs` — a three-block flow: 3 segments per wire, the block's lit bounding box is wider than tall (a circle would be square), the ports sit left/right of the centre in edit mode, `hier_layout` lines the chain up with `node_positions` agreeing, and a click selects the middle block. All fourteen graph suites pass; bench 100k: settle 4.48 ms/frame, hover 1.09 (the attr slot grew; both far under budget). Next: 7b, the flow panel itself swaps its canvas.

**Spec 031, stage 7b (2026-10-09): the flow panel on the engine.** `packages/editors/flow` drops the `dioxus-flow` dependency and hosts the engine exactly like the graph panel (`window.moonkale.flowViews[ID]`, `RENDER_JS`/`RENDER_WASM` from `moonkale-graph-assets` (the shared assets crate — extensions may not depend on each other, Milestone 18's layering check), `set_interaction("edit")`). The panel's `to_scene` is the whole translation: blocks become `rect` nodes sized by their port count, ports sit left/right coloured by `PortType`, wires are directed ortho edges (issue-red), and every node is **pinned** — the document owns coordinates, the canvas reports `moved` (enriched with `node_positions()` on drag end) and the panel harvests them back; a `set_graph` push matches by id and keeps live positions. The engine emits `connect`; the panel validates with `ext-api::flow::unify` and adds the wire — one wire per input port, a refusal shows a notice and re-pushes the scene without the gesture's wire (the renderer never mutates the model, ADR-0018). The parameter editor is one HTML side panel for the **selected** block (spec §7 — no per-node DOM), with spec 001's keyboard guard (typed keys stop at the panel root). `flow.mjs` was rewritten against the engine before anything was deleted: port drags by `port_screen_position`, palette adds single-fire, Layout via `hier_layout`, Save/Generate/reload/broken-file guard (#11) all green.

Two engine-side findings. (1) **Fit bounds now carry the nodes' rims** (`Graph::bounds_with_rims`, spec §2 sizes vary): `fit_bounds()` used node centres, and a flow block's half-width (46 world) dwarfs the fit's 40 px pad — the outermost ports landed flush at the canvas edge, where a wire drag's pointerdown hit the workspace *splitter* instead (dragging it shrank the editor and cascaded into a phantom palette click mid-reflow). Circles' radii count too, so the graph panel's fit shifts by a few px at most; all fourteen suites re-ran green. **Spec 031, stage 7c (2026-10-09): undo, the positioned editor, and the flow's parity list closed.** Three engine-side changes. (1) **A pinned node with an explicit `pos` is the host's to move** (`web.rs`'s incremental `set_graph`): known nodes still keep their live positions (the explorer's layout wins), but a pinned node carrying `pos` lands at the host's coordinates — undo restores a block's position and the canvas follows the document, which was impossible when the merge ignored `pos` for survivors.
