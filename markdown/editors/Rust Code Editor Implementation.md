## Syntax-aware Enter indentation (2026-10-05)

`native_indent.rs` plans Enter from the retained model's parsed highlight spans. It ignores string/comment punctuation, finds code triggers before trailing comments (including Python suite colons and Rust braces), and suppresses triggers inside multiline strings. Julia additionally reads grammar keyword tokens for functions, modules, structs, loops, if/else, try/catch/finally, let/begin/quote and do blocks, including incomplete headers while typing. HTML reads complete start-tag nodes, ignores attributes, void/self-closing tags and raw text, and splits matching adjacent tag pairs with an indented inner line and aligned closing tag. The planner shares `native_language::indentation` with engine configuration so tabs, spaces and width overrides agree.

Each Enter becomes one scalar-range Replace command through the normal engine delta/Workspace history pipeline; caret placement inside split pairs follows the edit. Backward/multiline selections use their normalized start and end; split-pair whitespace is consumed to align closers. Unknown or unavailable syntax preserves leading whitespace without punctuation guesses. Plain paste/IME remains literal and is not routed through this planner. This slice implements Enter behavior; closing-token alignment is implemented below; formatter-driven whole-document indentation and more language-specific policies remain open. ## Current integration (2026-10-05)

`RustCodeEditorPanel` in `packages/code-view/src/native_panel.rs` now uses `editor-core::EditorStateManager`, the model/adapter in `native_model.rs`, and the Dioxus view in `native_surface.rs`. The Code native extension delegates to this component; Markdown Source uses it when `Workspace::editor_for(node)` is `native`. CodeMirror remains the default and fallback. The previous controlled document textarea is replaced; `dioxus-code-editor` is no longer a dependency of code-view.

Workspace owns canonical `Document::text` and a `RevisionedDocument` session per `NodeId`. The editor revision is separate from the source's save/conflict version. `Workspace::editor_view_state<T>` supplies typed root-scoped models without adding a UI or engine dependency to ext-api. The Rust view slot contains the engine, first viewport row and handled shell command/reveal sequences. Panel remounts and switching implementations retain that slot; close/rename removes its registry entry. Root-scope allocations live until the application root is destroyed.

The engine owns caret, selection and text commands. Its native `TextDelta` edits use sequential Unicode scalar offsets. `delta_batch` validates each edit against the intermediate text and reduces the changes to one localized replacement in old-snapshot UTF-8 bytes. It does not compute a full-document prefix/suffix diff. The revisioned contract validates removed text, ranges and selection atomically. A stale model revision or canonical text mismatch discards the attempted input and replaces the engine from Workspace. CRLF is preserved in Workspace/saves while the engine works with normalized LF.

Caret/selection reports come directly from Rust state, converted to absolute UTF-16 offsets and LSP line/column. Backward selection, grapheme movement, pointer selection, selected replacement, shell/local undo/redo and host reveal are connected. Handled reveal requests are retained in the root-scoped slot so remounting does not replay an old request against newer text. Undo/redo use the shared Workspace snapshot history, so CodeMirror switching does not destroy the Rust history. External replacement/reload invalidates that history and selection. Restoring a caret uses MoveTo; restoring an actual range also uses SetSelection. This avoids editor-core's empty-selection state masking subsequent cursor movement.

The view requests only its measured viewport plus three overscan rows, with a 40-row initial estimate. editor-core wraps long lines into grid rows. Syntax token classes come from the Rust `dioxus-code::advanced::Buffer`; ordinary byte replacements update its tree through SourceEdit, while CRLF replacement reparses normalized text. Parser failure leaves an editable plain view. Theme styles and surface colours follow Moonkale theme tokens.

A tiny offscreen textarea receives composition/paste fragments only; it never contains the document or supplies caret/selection. A keyed single-item list remounts the sink after consumed input and restores focus, preventing old fragments accumulating. Composition preview is rendered at the Rust caret; outgoing-sink events cannot duplicate the commit. Browser copy/cut write the Rust selection into the native clipboard event, and paste arrives through the sink. Desktop shortcuts use a long-lived Rust arboard clipboard via `native-desktop`, enabled by the desktop app's `desktop` feature. There is no document::eval in the Rust panel or surface.
