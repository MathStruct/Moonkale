---
title: "Spec 025 — A five-button mouse is the expected input device"
tags: [spec, input, navigation]
status: required (2026-10-14)
---
Expect users to have a **5-button "gamer" mouse**: left, middle (wheel click), right, and the two thumb buttons (browser back/forward, buttons 4 and 5 in X/Wayland terms, `MouseEvent.button` 3 and 4 in the DOM).

What that should mean in Moonkale (to design with [[024]]):
- **Thumb buttons = navigation history**: back/forward through the documents and graph positions visited (the editor stack and the graph camera), like a browser — the most common use of these buttons and what people already expect.
- **Middle click** on a file, a symbol or a graph node: open in a new tab / new split without switching focus (the browser convention).
- **Double left click / right click on a symbol**: the actions of [[024]] (definition, graph focus); the context menu should list them so a two-button user is not locked out.
- Wheel + modifiers: Ctrl for zoom (graph, editor font later), Shift for horizontal scroll — already true in the graph.
- Bindings should be configurable next to the keybindings (Settings → Keybindings; a `mouse` section in the settings file), and the defaults must not conflict with the webview's own handling of buttons 3/4 (WebKitGTK maps them to history navigation of the *page* — Moonkale has to `preventDefault` them or the app "navigates back" out of itself; check on desktop, web and Android).

**Implemented scope (2026-10-28, WP-61):** configurable thumb/middle mappings,
window-local document/camera visits, background opening on Explorer, quick-open,
Links-panel files, graph nodes/symbol owners and table references, middle tab
closing and canvas pan. Alt+Enter in Go to File and the Explorer context menu
provide background opening from two-button/keyboard input. Shared capture guards
suppress page history; Chromium acceptance is in `mouse.mjs`. WebKitGTK and
Android verification, richer canvas context menus and inline editor-owned
symbol/link actions remain open. See [[Input Layouts]] for exact scope.

**2026-10-14 (Daniel):** a five-button mouse is now a **requirement for full functionality**, not only the expected device. The plan, with the default and extended mouse maps, keymap presets and other keyboard layouts, is [[Input Layouts]] (WP-61). Everything stays reachable with two buttons and the keyboard.
