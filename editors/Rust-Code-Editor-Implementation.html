Profile-led Rust highlighting (2026-10-15)

Other grammars still use dioxus-code’s buffer. The direct arborium-theme edge reuses the already-locked 2.18.2 package to preserve capture-to-class mapping; no new package/version or public extension API is introduced.

Unversioned diagnostics persist until publication; versioned ranges are invalidated on edits. Server startup/initialization and waiting callers have 30-second timeouts, with cancellation cleanup.
  • Workspace edits reconcile stale unmounted native sessions from current canonical text in a staged copy. Final identity, text, session and server-version checks still run before the atomic commit.
  • Same-position insertion followed by replacement is accepted; duplicate insertions and overlapping ranges remain rejected. Null completion edit fields are treated as absent. Actions with an edit and a command expose/apply the declared edit, matching the earlier client behavior; command-only actions remain unsupported and commands are never executed. M2 folding and matching brackets (2026-10-05)

There is one gutter control per starting line, using the widest range. Broken nesting does not produce a matched pair; unavailable highlighting leaves no derived folds/matches. Delimiter/Python folding is supplemented by the grammar providers below. Lean declarations/proofs use the dedicated layout provider below. Additional language-specific providers and full Python syntax folding remain open.

The folding-aware styled engine viewport supplies only visible rows and fold placeholders.   • RevisionedDocument::apply_in_place validates before mutation and determines no-ops locally. LSP updates compare each text/saved value once. Canonical Workspace/session/LSP copies and work proportional to an edited long line remain; this is not a constant-time typing claim.
  • CodeMirror now uses the native guarded staging/commit path: all targets and server versions are checked before changes, closed targets become unsaved documents, CRLF and per-file undo are preserved, and stale requests are rejected. Its view mirror uses normalized newlines, converts changes back to canonical CRLF, and publishes selections in canonical UTF-16 units. Rename reads the current cursor when committed.

The earlier LSP audit findings are covered by server removal/reset and automatic panel recovery, atomic multi-file workspace edits, and current-position rename requests. Graph-editor code was not changed.

Validation: workspace tests and warnings-denied all-target Clippy; 99 code-view tests with layout-fixture; native-desktop/layout-fixture Clippy; formatting, translation, colour and dependency checks. Chromium suites cover the second-review regressions (both editor backends), retained-tab/dock integration, code actions, rename, completion, hover, definitions, canonical Workspace editing and multiline presentation. Native XWayland acceptance passes pointer boundaries, canonical copy, typing/undo and real Pinyin with multiline presentation. These checks do not replace the remaining broader platform and real Markdown-provider acceptance gates.

2026-10-09 — Interactive preview block container

Added feature-gated native_widgets::PreviewBlock, a reusable container for provider-supplied content with expansion, unique accessibility targets and a guarded source-return action. Keyboard/pointer/clipboard events inside its content stay outside editor input. The synthetic block supports a local native input and natural measured content height. The native input owns its current value to avoid asynchronous controlled-input writes losing OS keystrokes. Widget state is local to its mounted revision; collapsing preserves content, and changing source revision recreates it.

native-editor-widgets.mjs verifies independent duplicate panes, event isolation, composition Escape, source anchor/focus, unmodified undo history, height alignment, delayed toggles, resize, scrolling and removal. native-editor-renderer.py --x11 --widgets --os-input selects a dedicated WebKit DOM probe and an owned-window OS runner. Real widget typing/navigation, Escape, source edit/undo and Edit source pass. Existing layout, multiline and integration browser suites pass, alongside 99 code-view tests, default/native-desktop/layout-fixture Clippy, desktop build, syntax/formatting and repository checks. The globally intercepted Ctrl-period shortcut is covered in Chromium rather than OS automation.

This is still an opt-in synthetic provider. It does not enable Markdown preview or change the default backend. General inline controls, persistent provider state and real widget-input IME remain future work. The next provider step needs its own bounded Markdown feature plan.

WP-03: live LSP UI acceptance — 2026-10-15

The implementation’s existing LSP features now run through the real rust-analyzer browser scenarios on either engine (LSP_EDITOR=native|codemirror). Shared tests check UTF-16 wire positions after non-BMP text in CRLF source, diagnostics and save, completion, F12, unsaved rename/stale cancellation, references and edit-based code actions. The test adapter reads rendered source rows, not the hidden input value, and uses narrow keyboard selections for cleanup without multiline source replacement. Editor-specific undo grouping and native proactive prompt cancellation remain legitimate behavior differences.

The desktop fixture optionally discovers a live installed server via the existing moonkale-lsp-local service, an optional desktop-only fixture dependency. With no MOONKALE_LSP_ROOT, it retains the deterministic transport. Its isolated runner creates its own Cargo workspace/target and display; a fixture-only WebKit DOM probe passes all seven LSP features with Unicode/CRLF and verifies that unsaved edits do not write the corpus. No new production connection, authority, JS editor-state bridge or runtime dependency is introduced. The probe’s eval acknowledgement keeps its report channel alive until Rust receives the result.

See Rust Code Editor Roadmap, Rust Code Editor Native Acceptance and the E2E README for commands, evidence and remaining gates. Command-only actions remain unsupported by the shared client; default cutover, physical-desktop CED-R22, Android and accessibility acceptance are still open.

NEXT-4: accessibility and backend migration — 2026-10-15

The surface exposes a file-named input with stable help and bounded canonical context, caret and selection endpoints through a polite atomic status. The virtualized reading region no longer claims to be a second editable textbox. Input focus is reachable by Tab, primary-M toggles focus traversal/indentation, primary-Enter follows source wiki-links, hover Escape restores input focus, and focus/reduced-motion styles use theme tokens. Actual Chromium AX and GTK WebKit AT-SPI trees are checked. This is bounded context, not a full accessible text mirror or speech transcript; details in Rust Code Editor Accessibility and Cutover.

The active Workspace UTF-16 selection is restored on Rust panel mount, preserving CRLF/non-BMP and reversed ranges across backend changes. DEFAULT_CODE_EDITOR remains codemirror and centralizes a later guarded default flip. Resolving the existing native preference activates the shipped adapter unless disabled; the core Code extension can honor it without the optional adapter in minimal builds. Stored settings, document bytes and per-document overrides are not rewritten. The full-app migration test covers live unsaved buffers and restored saved tabs. CodeMirror’s pre-switch private undo stack is not imported into Rust history.

WP-69 follow-up: preview typing and browser validation — 2026-10-17

The compact toolbar exposes more preview rows, making repeated geometry work more visible. Presentation collapse computation resolves endpoints against one scalar line-start table; row-only and zero-cell engine queries avoid reading full logical lines. Folding reuses a bounded three-entry parser/tree cache with UTF-8-safe incremental edits. Markdown highlighting retains captures for a narrowly checked, unhighlighted ASCII prose append at EOF, parsing normally for syntax-changing edits or edits elsewhere. Last measured Markdown row heights remain provisional estimates during revision changes, while exact revision guards continue to protect input geometry. See P-211 Preview row queries and folding repeated full text work for measurements and validation. The migration browser test waits for client hydration before submitting the Explorer form.

Native fixture follow-up also checks the complete keyboard path from ⋯ to hover and back, source contrast on both theme/selection backgrounds, and preview geometry/navigation. Virtualized-link tests reacquire after scrolling; table tests let queued row-height measurements publish before a real hit-map click. The contrast and latency limits are unchanged.
